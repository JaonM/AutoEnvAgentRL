# V2 沙箱任务泛化性优化目标

用户新增目标：在提高端到端良品率、优化反馈速度的同时，提高沙箱任务泛化性。

三项并列优化目标为：端到端训练就绪良品率、可比条件下的反馈速度、未见任务上的泛化良品率。每轮根因分析同时检查这三项，通用修复必须保留旧样本回归，并通过后续独立验证检查是否改善泛化。

## 验证范围

分别测量以下维度，避免把更换记录或数值等同于跨业务泛化：

1. 同类业务新实例：不同对象、数据、关系、数值与规模。已完成的 40 个扩展样本结果仅代表这一范围：30/40 良品（75%），复杂任务 9/16（56.25%），不能作为跨业务泛化成绩。
2. 未见业务规则：保留未用于修复的业务场景及规则组合，检验需求、沙箱行为、奖励和独立业务验收是否一致。
3. 未见任务组合：跨对象长链规划、检索与写入组合、多事务部分成功、撤销与条件授权。
4. 工具结构变化：改变工具命名、拆分与组合、分页方式和合法替代路径，并加入说明准确、实际可执行的干扰工具。
5. 用户与边界变化：口语、信息缺失、复合问题、偏好更正、拒绝、撤销，以及无匹配对象、时间边界、额度不足和规模变化。

## 实施与验收

- 已完成的 40 个同类新实例保留冻结结果，不混入新增测试或修复后回归以改变原始分母。
- 另建跨业务验证集。先声明场景划分、样本来源、难度比例、预算和指标，再生成、独立审查并冻结。验证集业务规则不得用于定向修复。
- 按业务族划分开发集与验证集；仅更换 ID、数值、关键词或随机种子不算未见业务。
- 通用修复优先作用于表达式语义、事务与授权机制、需求来源、评分契约和工具协议；不得按样本 ID 或特定业务名称硬编码通过路径。
- 保持单并发及完整轮次结束后统一修复；固定版本完成整轮，失败、超时、不确定及模拟用户故障保留并分别归因。
- 分别报告流水线合格率、独立业务通过率、实际自由对话 agent 成功率、训练就绪良品率，以及阶段耗时、调用次数和修复次数。
- 对各泛化维度报告分母、分子及置信区间，检查正确行为误扣分、错误行为得分和合法替代工具路径。业务奖励 95%、效率奖励 5% 的原则不变。
- 同类新实例与跨业务结果分开报告。跨业务首轮先建立基线，再预声明提升目标；不沿用同类样本的 75% 作为跨业务成绩。
- 合成验证证明工程范围内的表现；真实用户分布和实际 RL 学习效果仍需独立证据。任何有限测试均不能保证普遍泛化。

## 后续交付

交付跨业务验证集及冻结清单、业务族隔离证据、完整轮次结果、泛化失败根因、通用修复与旧样本回归证据。原有端到端良品率及反馈速度目标继续保留。

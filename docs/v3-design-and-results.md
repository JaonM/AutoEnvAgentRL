# V3 设计与结果记录

V3 是用纯 Python 生成 Agentic RL 业务沙箱的流水线，依靠相互独立的差分检查来认证沙箱，不引用 V1/V2 代码。
实现和命令见 `src/env_factory_v3/README.md`；本文记录目标、设计取舍、测量口径与结果。

## 目标

原始目标：把业务需求变成**行为正确**的可执行环境（工具、状态、奖励），且经得起独立验证。

2026-10-12 用户新增三项硬性目标，与正确性良品率并列验收：

1. **任务口吻符合自然用户**：开场不复述规则、费率、事务语义，不像应用题。
2. **奖励规则可学习**：真实策略能拿到信号；不能“什么都不做也得分”。
3. **模拟用户支持自由对话**：agent 用自然语言交流、看不到槽位键；同意判定保持确定，奖励仍然精确。

## 设计

```
request ─► schema 会话 ─► answer_schema
                │
     ┌──────────┴──────────┐   并行、隔离、同一 schema
  author: env.py        oracle: oracle.py（看不到 env.py）
     └──────────┬──────────┘
  差分：原始世界 + 每个批准翻转 + 20 个扰动世界
     │ 不一致 → 仲裁（只能逐字引用用户请求/业务规则；歧义 → 报告）
  分支审计：拒绝后跳过后续步骤（两边同错）→ 独立审计 → 两边同时修复
  扰动审计：改动任务作用的行而结果不变（两边同错）→ 独立审计 → 修复或排除该世界
  gates：static · differential · negatives · category · http
     │
  bundle（哈希 + 平台签名）─► docker 镜像（禁网容器内重跑全部 gate）─► rl 训练 / policy gate
```

要点：

- **两边同错是差分检查的结构性盲区。** 分支审计和扰动审计都先用确定性信号找可疑世界，再交给只看 brief 的新会话裁决，
  要求逐字引用；歧义不由模型决定，而是排除或报告给业务方。
- **奖励不由作者编写。** `0.95·业务 + 0.05·效率`，业务分来自 oracle；效率分只在成功时给；未经授权的写入整体清零。
- **agent 看到的界面只有一份定义**（`agent_view.py`），训练和 policy gate 共用，gate 测的正是训练时的界面。
- **工具说明强制带类型和逐参数说明**（static gate）：agent 除此之外看不到别的。
- **交付**：`docker BUNDLE` 构建加固镜像，并在 `--network=none`、只读根、`cap-drop ALL`、非 root 下于容器内重跑全部 gate；
  平台代码一变所有 bundle 失效，`verify --resign` 全部 gate 通过才重新签名。

## 结果

真值（truth）是 V2 阶段为冻结集单独编写的独立 oracle，只用于评估，从不给流水线中的模型看。
“良品” = 通过全部 gate 且与 truth 一致（原始世界与批准翻转上的最终状态和答案）。

| 运行 | 样本 | 良品 | 误放行 | V2 同样本 |
| --- | --- | --- | --- | --- |
| M1 01:02（cross 复杂 8） | 4 个业务族 | 6/8 | 1 | 0/24 |
| M1 01:27（cross 复杂 8） | 同上 | 7/8 | 0 | 0/24 |
| 泛化 10（v2 比例 2:2:2:4） | cross 4 族 | 9/10 | 0 | 8/30 |
| **fresh20（未见业务族）** | 包裹/停车/仓储/档案 | **20/20** | 0 | 16/60 |
| **fresh20 P1 重建**（类型化工具、扰动审计、预算 2） | 同上 | **20/20** | 0 | 16/60 |

- fresh20 是 V3 开发中从未使用的留出集；20/20 的 Wilson 95% 区间约 84%–100%。
- 样本 9 的误放行（env 与 oracle 都在用户拒绝第一笔后停止）促成了分支审计；之后该样本被拦下，预算为 2 时修复成功。
- 奖励反事实（fresh20）：单点篡改答案或状态 23506 次，**假阳性 0**；应判成功的 583 次，**假阴性 0**。
- 扰动审计（P1 重建）：11 个构建触发，48 个世界中 46 个 `consistent`、2 个 `should_change`（一个修复成功、一个世界被排除）；
  回放验证中把“已失效订阅仍退款”判为 `ambiguous`，对 20 个合法不变的世界没有误判。
- 训练接入：Qwen3-0.6B GRPO 在 V3 沙箱上经 Docker 后端完成训练并产生真实更新（simple 任务 3/3 成功），无残留容器。
- **开场语自然化后重建**（fresh20-natural-01，自然度 3.5 → 4.95）：**20/20 良品，误放行 0**，
  20/20 具备自由对话能力（`approval_key` 与参考解一致）——改写开场语没有改变任务语义。
- **policy gate**（deepseek-flash，k=4）：结构化用户 79/80 成功；自由对话 67/80（83.8%）。自由对话的失败
  主要来自协议：agent 用普通文字向用户提问，却被当作最终答案结束。已改为“普通文字＝对用户说话，
  只有 v3_answer 结束”（见下节），需重测。
- **目标学习者（Qwen3-4B，GRPO）**：复杂任务 fresh-14 两次各 4 条 rollout 奖励为 [0,1,0,1] 与 [0,0,0,1]——
  成功率处于中间区间，组内有方差，GRPO 有信号；0.6B 几乎全错、deepseek 几乎全对，均无信号。
  “奖励可学习”因此取决于目标模型，需按目标学习者测量成功率与组内方差。
- **第三方 oracle（生成任务的真值替代）**：另一家模型只看 brief 写 oracle，与交付 env 比对。
  已知正确的 20 个：20/20 一致（无误报）；已知错误的 2 个：拒绝级联错误被同样误读而漏掉，
  扰动世界错误被发现。只能作弱证据，不能替代手写真值。

## 设计取舍记录

- **最终答案保持结构化（`v3_answer`），不做自然语言答复的 LLM 抽取判分。** 抽取会给奖励引入评审噪声，
  与“奖励可学习”冲突；自由对话模式下 agent 用普通文字与用户自然交流，最后像客服填工单一样提交
  结构化结论——对话自然，判分精确。
- **同意判定不交给模拟用户。** LLM 只负责说话；平台用 `approval_key(tool, args, facts)` 与用户批准事实决定。
- **`approval_key` 只是自由对话的就绪条件**，不进入 static gate，结构化用户的 bundle 不因缺少它而失效。

## 测量口径与局限

- 答案比对只比较 truth 答案中的数值与 ID；字段命名不同导致的不一致需人工复核（已逐条记录）。
- truth 只在原始世界与批准翻转上验证过，扰动世界只作诊断（订阅 truth 读取固定账期参数等已知缺陷）。
- 40 个冻结样本以外没有外部真值；cross 复杂样本在开发中反复使用，结果受污染，fresh20 才是干净的留出。
- 良品率衡量“环境逻辑正确”，不等于训练价值；后者需要 policy gate、组内方差与真实训练曲线。

# 数据集驱动任务生成

原始文件支持 `.csv`、`.tsv`、`.json`、`.jsonl`、`.ndjson`、`.xlsx`、`.parquet`、`.sqlite`、`.sqlite3` 、`.db`、`.zip`、`.gz`、`.tar`、`.tar.gz` 和 `.tgz`。压缩包中可包含前述表格格式；JSON 需要对象数组或包含单个对象数组的根对象；Excel 与 SQLite 选择第一个满足基本行列数量的工作表或表。数据源默认上限为 5 GB，可通过 `--dataset-max-gb` 调整；读取时只采样前 500 行，大型 CSV、TSV、JSON/JSONL、Parquet、Excel 与 SQLite 不整体载入内存；字段仍须满足唯一业务 ID、可分组字段和数值字段的任务生成条件。Excel、Parquet 和大体积 JSON 的流式读取由项目依赖 `openpyxl`、`pyarrow`、`ijson` 提供。压缩包只读取选中的表格成员；必要时将单个二进制成员临时解压到磁盘，并按大小上限检查。

`./scripts/generate_task.sh` 默认走知识图谱＋数据集路径：先从已审核的场景关系选源，生成时核对原始文件、许可、字段和哈希。Kaggle 的 10,000 条索引和 DATA.GOV.HK 的 3,822 条索引可用 `uv run python scripts/diagnostics/sync_graph_dataset_links.py` 导入图谱作为目录元数据；目录收录不等于允许生成。DATA.GOV.HK 目录记录中文标题、提供机构、类别、资源名称及格式，目前只有“格价资讯通”原始来源获批准。`--dataset-platform balanced --count 2` 按 1:1 分配两种来源。若需原数据集路径，显式使用 `--generation-source dataset`；此时可通过 `--dataset-ref owner/slug` 或 `--dataset-file path.xlsx --dataset-url URL` 固定来源。原始文件按需下载到忽略 Git 的 `data/sources/`；JSON 目录索引纳入 Git。

图谱构建入口 `./scripts/build_graph.sh` 现在顺序执行 Scene 扩展、完整目录同步、关系注册表核验和 Scene→Dataset 写入。已有 Scene 只需补数据时可运行 `./scripts/build_graph.sh --datasets-only`；目录未变时再加 `--links-only`。候选目录只能用来发现可能的来源；每个准入数据集需固定版本、许可、具体原始文件路径和 SHA-256，再验证唯一 ID、分组、数值字段及组内样本。`config/graph_dataset_links.json` 中的 `parent_scene` 把确有原始分组值支撑的细分 Scene 连接到上位 Scene；关系在写图谱前全部重新核验，任务生成前也会复核。当前已核验八个 Kaggle 来源和一个香港商品价格来源，共 54 条关系；其中 43 条是注册表中的细分 Scene 映射，复用场景后对应 38 条不同的层级边。五个新增来源覆盖线上订单、门店交易、超市收银、商场购物和商品销售；其数值字段分别是订单总金额、商品单价、收银收入、商品价格与商品单价，不将单价误称为订单总额。酒店数据固定使用 `reservations.csv`，不会因同一数据集另有住客资料表而自动换表。扩展更多数据源仍需人工判断业务语义和来源适配性。

当前入口先读取表格文件前 500 行，选择唯一记录 ID、可重复的业务分组字段和数值字段；只将所需原始列及行投影到任务业务表，不合成业务值。数据集用于构造后台业务表、工具真值和奖励答案键，不作为用户任务的叙述主题。首先由 `dataset_business_scenario` 阶段根据图谱场景、数据集标题、安全列和少量投影样本分析业务实体、用户角色与业务场景；然后由 `dataset_task_design` 阶段根据审核关系中的业务称呼和任务路由生成用户请求，并校验题面体现所选场景。直接回答任务在公开材料中提供 A/B 两笔业务信息及比较值；单工具与多步任务只提供起始业务标识。用户可自然说“这笔”“这单”，无须说“附上的凭证”。原始数据集标题、字段名和记录 ID 不写进请求正文。单工具按标识查后台业务表；多步任务先查询分组，再查询同类最高、最低、平均值或数量。答案由选中源行确定性计算，作为奖励答案键。后续 Pipeline 生成环境、工具、奖励和验收契约，并运行任务构建性门禁。

每个任务目录中的 `source_selection.json` 记录来源、原始文件 SHA-256、业务场景分析、投影列、选中记录 ID 和答案键；图谱路径还记录所用场景、数据集键和关系依据。`task.json` 的 `artifacts.dataset_source` 保留来源、哈希及许可标识。生成前会拒绝可能包含联系方式或长文本的投影值。失败的候选与路由尝试写入 `sample_manifest.json`。现阶段支持 CSV、TSV、JSON、JSONL/NDJSON、XLSX、Parquet、SQLite 与包含这些文件的压缩包中具备上述三类字段的只读 `QA` 任务。旧关键词图谱路径可用 `--generation-source graph_keywords` 显式调用。

Kaggle 和 DATA.GOV.HK 的选中原始行可直接作为沙箱业务数据，任务清单会声明 `public_dataset`、来源平台、URL、源文件哈希、压缩包内所选成员和许可标识。本地数据文件需同时提供对应的 `--dataset-url` 才能获得公开数据集来源声明；仅有本地文件路径会标记为未核验来源。公开数据集不声明为合成数据，其真实用户数据状态为未确定。出站前仍需通过凭证和疑似个人信息扫描，素材分发权利另行核对。

本地验证使用旅游数据集生成了直接回答、单工具、多步工具任务，并用另一份零售数据集生成了多步工具及默认选源的直接回答任务；五个任务均通过构建性门禁，离线任务质量分数分别为 10、10、9.35、9.35、10。这些结果验证任务契约和数据来源绑定；尚未包含对应沙箱构建、真实 rollout 或生产认证。

题面解耦后，又用已核验的零售数据集生成了一个多步样本：用户请求为“我附上了一张消费凭证，想请你帮我看看它属于哪个商品类别。另外，在同类消费里，金额最低的是哪一笔，具体是多少？”，公开凭证只含交易号；后台仍需 `lookup_record` 与依赖其结果的 `list_group_records`。该样本通过任务构建性门禁。口语模型曾把单张凭证误写成“两笔”，现已加入数量一致性校验；此验证仍不等于完整沙箱 rollout 或训练收益验证。

上述样本属于改造前的历史结果。场景分析版的多步样本题面为：“我在核对零售交易的商品类别，这单属于哪个类别？同类交易里总金额最低的那笔是哪一笔、金额多少？”公开业务信息只给交易编号；场景分析与选中源行保存在 `source_selection.json`。题面设计若缺业务动机、出现“先…然后…”操作话术、遗漏最低交易的身份或引入未给出的营销背景，会在该阶段局部重写，最多三次，再进入工具、奖励与验收生成。该样本通过候选构建性门禁，离线质量评分 9.35；仍需完整沙箱 rollout 才能判断训练价值。

# 生成与沙箱一致性改造

## 责任边界

模型生成业务语义，平台编译结构与执行机制，构建模型仅实现未覆盖的业务扩展。`app.py`、共享运行时、已声明化工具和指标不允许被扩展覆盖。旧沙箱需要重新生成平台文件并重新验收。

## 任务生成

领域词汇不再直接决定任务是否串题或具备训练资格。原有领域冲突表、烹饪/购物清单、编程/活动、普通话重音等特判已删除；语义一致性继续由任务 grounding、动作对齐及最终契约审计负责。静态评分只表示结构与可执行证据，不是语义正确证明。

修复耗尽后保留失败，不再将任务替换为固定低风险文本题；噪声工具审计失败触发反馈重试，不再降级为固定骰子工具。运行时仅按工具契约和独立 fixture 执行，不按名称前缀分派特殊行为。旧评分需要重新计算；旧生成沙箱不会自动迁移，含旧兜底语义的样本应重新生成、构建并验收。

- stateful 在动作生成前冻结 `business_goal_contract.row_predicates`（table、where、values、count）；初态不能已经满足目标。最终 TaskSpec 保存这些谓词及主键。
- 能力依赖来自 `capability_plan`，不是奖励关键步骤；过程奖励不应限制业务图规模。
- 模型提供成功场景工具调用计划；reset、回答 fixture、奖励检查及失败基线由平台组装。结构约束不能代替语义审计。
- 噪声工具使用独立数据和参数过滤，不向 Agent 暴露 noise 标签。
- 各阶段结构/语义错误反馈重试，工具实现规格逐项修复；仍不满足契约则拒绝生成。
- 批次任一任务失败，CLI 返回非零；保留成功任务，不覆盖。

## 工具和持久化

- SQLite 保存 episode、业务 JSON 状态、事件和幂等响应，开启 WAL、外键和显式事务。业务写入、输出契约校验、事件、幂等结果共享事务，异常回滚。
- 同一幂等键、相同请求返回缓存；不同参数返回 409。
- Trainer 应设置 `X-Episode-ID`，与 reset 的 episode_id 一致。不传时兼容最近 episode，不适合并发 episode 路由。
- 独立保存 schema，允许空表重新插入；写入检查类型、主键、unique、外键；数值按数值排序。
- 参数化外部 fixture 精确匹配 arguments；无匹配报告不可用，不伪造固定成功结果。
- 当前适合小型结构化状态，不是通用关系数据库或分布式事务引擎。整请求事务会串行化写入，外部 LLM 等待期间仍可能占锁。高并发训练宜每个 worker 独立数据库；后续需版本校验再缩小事务范围。

## 奖励和用户模拟

- 平台提供真实状态、初态、轨迹及最终回答，扩展不能覆盖这些真值。
- stateful 完成奖励检查目标谓词、初态未满足、状态变化和无关行/字段保护，不以工具覆盖率替代成功。
- 支持成功路径和错误后恢复；有结果引用的边检查生产者结果与消费者参数一致。
- `external_llm_judge` 由平台统一执行标签约束评估，不让构建模型硬编码答案。其他未编译 hybrid 等扩展仍需审查。
- 离线 mock 只检查成功回答 fixture 一致性，记录 `semantic_verification=false`，不证明语义正确；生产外部评估不可用时保守降级。
- User Simulator 的外部 LLM 失败时保持 unmatched/unrecognized，不因 Agent 声称完成而推进状态，受恢复次数和轮数上限约束。

## 证据等级及剩余工作

静态任务评分、离线执行验收、真实模型 rollout 是不同证据。离线报告声明未验证 live rollout；评分缓存绑定代码、数据、测试指纹。反事实运行器内部错误不算作因果性证明。

回归覆盖事务回滚、重启/reset、episode 隔离、并发更新、数据约束、奖励真值、参数因果关系、模型协议和 scaffold 集成。仍需真实 stateful 多轮 rollout、外部能力可用性验证、语义评估校准和持续样本统计；测试通过不等于这些已完成。

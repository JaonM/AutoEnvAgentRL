# GPT-6-Astra 主链路与良品率优化方案

## 当前变更与证据

任务生成、沙箱构建及独立审查的 Codex 默认模型统一为 `gpt-6-astra`。
`--code-agent-model` 控制任务生成；`--sandbox-model` 控制构建及独立审查。其他 CLI 的构建模型默认继承任务模型。live、用户模拟器、奖励评估与 RL 策略模型仍由各自配置控制。

2026-10-04 固定失败样本实验已有三组完整配对：Astra 1/3，通过率 33.3%；Luna 0/3。第四组 Astra 网络中断，Luna 未启动，均不计入能力比较。通过包含编译、固定反例、独立审查和 Docker HTTP 验收，不代表完成训练认证。三条有效样本的端到端耗时中位数：Astra 650 秒，Luna 358 秒；失败也包含在耗时统计中。这是固定失败任务的修复实验，不能外推新任务良品率。

证据目录：`output/model_comparison_20261003_combined/`。切换默认模型后平台源码指纹发生变化；后续实验使用新版本和新输出目录，旧记录保持原样。

## P0：先消除共同根因

### 1. 统一动态业务契约

扩展已有 business_contract，显式定义“目标实体、授权数量、决策时状态、允许改变字段、成功结果”。同一实体绑定生成写入目标、身份检查、完成条件、奖励谓词和无关数据保护范围。

- 实体从已观察的查询结果绑定，避免 artifact_id、SKU 等私有行标识分散写死。
- 数量明确来自用户授权还是工单查询；若二者冲突，必须先澄清。库存检查、扣减和奖励使用同一数量表达式。
- 扣减使用事务开始时当前状态；查询快照需要版本检查，过期则重新读取。
- 同一幂等请求重放返回原提交结果，不重复扣减，也不以重放后的状态重算目标。
- 静态公共业务约束允许常量，不把所有常量一律判错。

验收：固定样本替换合法实体 ID、SKU、需求数量和初始库存，正确轨迹通过；超授权、库存不足、错误实体与无关行写入被拒绝，状态不被部分修改。

### 2. 将故障恢复从固定动作序列改为业务状态机

平台明确未提交、已提交但响应丢失、已确认三个状态。提交后超时允许“查询确认”或“同键重放”两条合法路径。成功依据提交证据、业务状态及授权，避免强制重复提交。

参考轨迹区分必要业务动作、恢复动作和可选观察。删除必要动作必须失去对应奖励；删除可选复查不应导致整个沙箱不合格。不要通过增加强制依赖让冗余操作看似必要。

验收：查询确认路径、同键重放路径都通过；重复扣减、未提交却报告成功、漏做必要动作都失败。

### 3. 验收意见必须有可执行证据

建立统一 finding 格式：规则、源路径、输入变更、实际调用、预期、实测、归因、修复位置。模型提出的反例先回放：复现失败才作为已证实缺陷；未复现或不可执行的意见进入待复核，不直接宣称缺陷成立。

分别记录业务错误、参考轨迹冗余、门禁误拒、评审输出无效、模型服务异常。保持奖励防作弊硬门禁；评审 JSON 错误和网络超时不混入模型质量分母。

验收：本轮所有最终拒绝意见都有回放结果；同一源文件重复验收结果稳定，错误报告不会触发无依据修复。

## P1：前置控制生成质量与修复收敛

### 4. 用户剧本由信息依赖生成

为每个阶段声明未知信息、信息来源、授权范围和后续消费者。前置检查单值 enum 泄露用户选择、已明确事项重复确认、虚构多步交互；保留真正改变范围或有业务后果的授权。

验收：所有必需交互提供新信息或必要授权；工具描述不提前暴露私人选择；日期更改、拒绝授权与澄清分支有实际验证。

### 5. 编译器和业务运行时承担通用实现

Astra 负责业务定义和异常分支，平台生成标准查询、事务写入、校验、幂等、故障注入与奖励绑定。复杂自定义代码仅用于脚手架无法表达的部分。已有实现优先扩展，避免新增平行流水线。

按“契约静态检查 → 本地完整回放与反例 → 独立审查 → Docker → live → 训练认证”执行；便宜门禁先行。编译及反例证据复用必须绑定源文件与运行时指纹。

### 6. 有界、定点修复

一次修复处理同一根因的所有关联字段，禁止只改一个硬编码数字。反馈按依赖聚合；完整回放保护其他场景。相同缺陷指纹连续出现则停止该样本并转平台问题，避免重复付费。

生成、修复、评审、Docker、live 分别记耗时与 token；网络重连使用独立次数和时间预算，不消耗业务修复轮次。600 秒暂保持现有实验默认，5 分钟只作为观测目标；不以延长重试代替修复根因。

## P2：验证提升后再扩大生成

1. 固定四个失败样本，先完成上述 P0，再在冻结平台版本上验证；目标四例全部通过确定性回放、正负反例、Docker 和训练认证。
2. 再运行两轮各五个新任务，固定图谱切片、复杂度配比、预算和模型；每个样本只按预先约定轮次修复，禁止挑选最好一次。
3. 报告原始计数及分阶段比例：前置合格/生成总数、Docker 通过/进入构建数、训练就绪/生成总数；另列基础设施异常。小样本展示区间或明确不确定性。
4. 发布标准：无已知奖励绕过与错误写入；固定集无回归；新样本训练就绪率较基线提升。10 个新样本仅用于试运行方向判断，扩大样本后再估计稳定生产良品率。

## 施工顺序与边界

先做动态实体/数量/事务契约，再做恢复状态机与门禁校准，再做证据回放，最后优化剧本生成和修复调度。每一步复用固定失败样本检验，完成 P0 后才生成新题。模型切换已实施；以上平台能力改造为待施工方案，不标记为已完成。

## 2026-10-04 施工记录

已实现并接入主链路：

- `business_contract.facts` 共享表达式及有界展开；`state_targets.identity` 由查询证据生成统一身份约束、目标与奖励。
- 生命周期守卫支持可信表达式；`operations.observed` 校验提交时状态与决策快照一致，缺失证据拒绝写入。
- 已提交但响应丢失的同键重放不再引入额外的强制重提依赖；幂等载荷校验保持有效。
- 可选重复只读观察必须通过“删除后仍满分”的正向回放，生成端、服务端及独立认证一致验证；不能豁免写入或首次读取。
- 模型审查附加有界的数据变更回放与源指纹；回放与语义判断分开，无法判定的意见保留待复核。
- 用户私有选择被绑定参数 singleton enum/const 唯一公开时，前置拒绝。
- 修复记录缺陷指纹，重复缺陷停止继续修复并标记需平台排查。

实测：四个固定样本本地完整回放、交付预检、真实 Docker HTTP 回放全部通过；新增“查询确认而不重复提交”“物料 SKU 改变”“需求数量改变”三个正向变体通过。样本使用保存的候选并迁移到平台通用表达式能力，不是一次全新自动生成实验。

证据：`output/astra_platform_regression_20261004/results.json`、`counterexamples.json`、`docker_results.json`。`training_ready` 仍为 false。

仍未完成：将全部语义审查意见变成可自动裁决的轨迹；完整恢复状态机及刷新快照的续跑策略；统一网络重连预算与分阶段费用统计；四例独立语义复审和 live 训练认证；两轮各五个新任务。Astra 复审已尝试，但出现连接拒绝/请求超时，异常独立记录于 `review_results.json`。在这些门槛完成前，不宣称端到端良品率达 100%，不进入新任务放量。


### 决策表与验收校准（本次增量）

- 新增可选 `decision_table`，复用原执行路由，枚举最多三个布尔决策，提前拒绝遗漏、重叠和缺失回放。没有新建另一条构建流水线。
- 分支可通过 `goal_values` 定义同一组共享目标字段；编译器统一生成条件目标和奖励。分支与目标共享 `business_contract.facts`，未知事实拒绝编译。
- Astra 作者提示与作者手册已接入上述约定；旧 `execution_routes` 仍兼容。新增生成服务验证覆盖写入和正确不写入两条路径。
- 独立审查明确原始目标优先、工具返回值的实际选择语义；不得仅凭工具文案增加强制重试义务。
- 审查数据回放明确标记 `contract_frozen: false`，不能当作固定契约漏洞已经复现的证据；语义意见仍待裁决，不自动翻转通过状态。

此决策表证明的是已声明布尔决策的组合覆盖，不能证明模型已提取全部自然语言条件。授权条款绑定、固定契约轨迹反例、live 认证及此前列出的恢复/网络预算工作继续保留为待完成项。

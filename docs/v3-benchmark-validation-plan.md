# V3 方法有效性验证实验方案：Qwen3-0.6B 在 τ²-bench 与 BFCL 上的显著提升

分支：`v3-bench-validation`。本文是预先登记的实验方案：判定标准、统计方法、对比组和停止条件都在训练开始前定好，
训练过程中不再修改；如果确实需要修改，在文末记录修改内容和原因。

## 1. 目标与"显著提升"的定义

本项目方法指：V3 生产线自动生成业务沙箱，用老师示范做 SFT 冷启动，再在沙箱里做 GRPO。训练全程不接触两个 benchmark 的任何数据。

要回答的问题是：Qwen3-0.6B 经过本项目方法训练之后，在两个外部 agent benchmark 上是否有**统计显著、且幅度可观**的提升。

| 编号 | 指标 | 显著提升的判定（两条都要满足） |
|---|---|---|
| H1 主指标 | τ²-bench airline + retail 的 pass^1（164 题，每题 4 次） | C 组比 A 组高 **≥ 0.10（绝对值）**，且配对检验 p < 0.05 |
| H2 主指标 | BFCL 多轮（800 题，贪心解码） | C 组比 A 组高 **≥ 5 个百分点**，且 McNemar 检验 p < 0.05 |
| H3 归因 | 同上两项 | C 组高于 B 组（RL 有增量）；B 组高于 A 组（SFT 有增量） |
| H4 不退化 | BFCL 单轮非 live 类别 | C 组比 A 组下降不超过 2 个百分点 |

H1 和 H2 同时成立，才算"显著提升"。H3 用来说明提升来自哪个环节，H4 用来排除"牺牲通用能力换分数"。

## 2. Benchmark、数据与评测协议

### τ²-bench（主指标）

- **题目**：airline 50 题 + retail 114 题，共 164 题，全部使用（官方训练/测试划分只用于对照汇报）。telecom 单独报告，不计入主指标：它要求用户自己操作设备，本项目没有这种交互模式。
- **每题跑 4 次**：报告 pass^1（4 次成功率的平均）和 pass^4（4 次全部成功的比例）。每个模型共 656 个 episode。
- **用户模拟器**：固定为 deepseek-flash，并记录具体模型版本（官方默认是 gpt-4.1，这一点作为偏差注明）。四组共用同一个模拟器和同一组随机种子。
- **判分**：官方评测器（数据库状态与告知信息相乘）。最大步数取官方默认的 100。
- **领域性质**：airline 是最干净的迁移指标（训练时屏蔽了航空领域）。retail 和训练池中的售后退换类业务相近，所以分开报告。

### BFCL（主指标与不退化对照）

- **多轮**：base、miss_func、miss_param、long_context，各 200 题，共 800 题，贪心解码，按官方评测器判分（状态与执行路径）。装好的包是 v4，多轮数据沿用 v3，这一点尚未核实，正式评测前确认。
- **单轮非 live**：simple、multiple、parallel、parallel_multiple，作为 H4 的退化对照。
- **接入方式**：使用 BFCL 自带的 `Qwen/Qwen3-0.6B-FC`，由它按 Qwen 模板拼接提示，通过 `--skip-server-setup` 连接自建服务的 `/v1/completions`。

### 推理服务（四组共用）

自建一个本地 OpenAI 兼容服务，加载 MLX 格式的 Qwen3-0.6B 或训练后的检查点，提供两个接口：

- `/v1/chat/completions`：供 τ²-bench 使用。复用 rl `Policy` 的对话渲染和工具调用解析，保证评测时的格式和训练时完全一致；
- `/v1/completions`：供 BFCL 使用，原样补全它拼好的提示。

四组的解码参数完全相同：不带思考，τ²-bench 用官方默认温度，BFCL 用贪心解码。上下文上限设为 32k，Qwen3-0.6B 原生支持。

## 3. 对比组

| 组 | 内容 | 作用 |
|---|---|---|
| A | 原始 Qwen3-0.6B | 基线 |
| B | A + SFT（V3 沙箱上 deepseek 的成功示范） | 衡量 SFT 冷启动的贡献 |
| C | B + GRPO（V3 沙箱） | **主要结论**：本项目完整方法 |
| D（消融） | A + GRPO，不做 SFT | 说明 SFT 冷启动是否必要 |
| R（参照） | 原始 Qwen3-1.7B | 只作量级参照：提升后的 0.6B 接近哪个规格 |

第二期（视第一期结果决定）：带推理的 SFT，加 think 模式的 RL。

## 4. 训练数据设计（决定能否迁移的关键）

两个 benchmark 考察的能力，和当前 V3 训练池之间有几处明显差距。下面每一项都是为了迁移而做的设计，其中 4.1 和 4.2 需要改动生成流程：

### 4.1 语言：补充英文沙箱（需要改生成流程）

τ²-bench 和 BFCL 全部是英文：政策、工具、用户都用英文，而 V3 目前只生成中文。对 0.6B 来说，语言不一致会严重削弱迁移效果。
**方案**：V3 生成流程增加语言选项（开场白、对外政策、用户模拟器人设、system 提示），训练池中英文沙箱占 **≥ 50%**。

### 4.2 τ²-bench 特有的行为（需要增加任务形态）

- **按政策拒绝**：用户提出政策不允许的请求，正确做法是不执行写操作，并解释原因。τ²-bench 大量考察这一点。新增 `refusal` 形态，占约 15%。
- **先核实身份**：τ²-bench 的任务要先通过姓名、邮编等找到用户，才能操作。在复杂任务中加入"核实身份后才能查询或修改"的规则，占复杂任务的一半。
- **转人工**：政策规定的特定情况必须转人工客服。少量任务提供转人工工具，转人工也是一种正确的结局。

### 4.3 已具备的对齐（无需改动）

- 自由对话的模拟用户，用户道别即结束对话；
- 不提供提交工具，靠"把结果告诉用户"来交付，答案从 agent 说过的话里抽取；
- agent 只看对外政策，不看实现规格；
- 写操作前必须征得用户同意；
- 工具是业务 API 风格，规则判断留给 agent；
- 平台工具名每个 episode 随机，避免背下工具名。

### 4.4 规模

- **训练沙箱**：用 `run_pipeline.sh` 生成 **200 个**（dev 划分，航空和电信领域已屏蔽）。比例为：direct 15%、simple 15%、普通多步 20%、复杂多步 25%、拒绝 15%、主观 10%。预计良品率约 80%，可用约 160 个。
- **训练/留出划分**：按领域划分，85% 训练，15% 留出，只用于 RL 检查点选择和过拟合监控。
- **示范**：deepseek 在训练沙箱上采集，自由对话、不提供提交工具、带客服口吻要求，每个沙箱 6 个 episode（覆盖原始、审批翻转、扰动世界），只保留成功的轨迹，预计约 800 条。推理内容另行保存，供第二期使用。

## 5. 训练配置

### SFT（B 组）

- Qwen3-0.6B BF16 全参训练，一条示范一个样本，只对 assistant 回合计算损失；
- 学习率 1e-5，最多 1.5 个 epoch；
- 按留出领域计算验证损失并早停。

### GRPO（C 组；D 组从 A 开始）

- **任务筛选**：先用 B 组模型对训练沙箱测 pass@4，只保留成功率在 0 和 1 之间的沙箱；
- **参数**：每组 8 条 rollout，每个 episode 最多 24 步，上下文 16k，2–3 个 epoch，保留 KL 约束；
- **奖励**：V3 现有规则（最终状态 + 答案字段，答案从说过的话里抽取；主观任务用 rubric）；
- **检查点选择**：只依据 V3 留出领域的成功率。**不在任何 benchmark 数据上选检查点或调参**，以免对测试集过拟合。

## 6. 统计分析

- **τ²-bench**：以题为单位配对（同一题在两组各跑 4 次），对每题的成功率差做配对检验（Wilcoxon 符号秩检验，配合 10,000 次配对 bootstrap 给出 95% 置信区间）。
  - 检验力估算：164 题、每题 4 次、基线约 0.1 时，能检出的最小差异约 0.06–0.08。H1 要求的 0.10 有足够检验力。
- **BFCL**：每题一个结果，两组配对，用 McNemar 检验，800 题能检出约 4 个百分点的差异。
- **多重比较**：A 对 C 是预先指定的主比较，不做校正；其余比较（B、D、R）属于探索性分析，按 Holm 方法校正。
- **报告内容**：分领域、分类别的成绩，置信区间，结束原因分布（用户结束、步数用完、调用不存在的工具等），失败案例分类。

## 7. 判定节点与停止条件

| 节点 | 检查什么 | 不满足时怎么办 |
|---|---|---|
| G0 基线 | A 组的 τ² pass^1 和 BFCL 多轮成绩；heldout 命名探针 | 只记录，不停止 |
| G1 SFT 后 | B 组在 τ² 上至少比 A 高 0.03，或 BFCL 多轮至少高 2 个百分点 | 先排查格式和语言迁移问题（看失败对话），修好再进入 RL |
| G2 RL 中 | V3 留出成功率在上升，KL 没有失控 | 调整学习率或筛选范围，不改评测 |
| G3 终评 | 按第 1 节判定 | 如实报告不显著的结果，并分析原因 |

## 8. 防污染

- 任何阶段都不使用两个 benchmark 的数据、政策文档或任务描述；
- 生成训练沙箱时屏蔽航空、电信相关领域，用 `RESERVED_FOR_EVAL` 实现，已提交；
- 老师模型 deepseek 只在 V3 沙箱上采集示范，不接触 benchmark；
- 终评之前不查看 benchmark 的单题结果，只在 G1 节点看汇总成绩和失败类型。

| 步骤 | 预计耗时 |

| 生成 200 个训练沙箱（codex，parallel 3） | 约 8–10 小时 |
| 采集示范（deepseek API） | 约 2 小时 |

## 10. 主要风险

| 风险 | 对策 |
|---|---|
| 0.6B 能力上限太低，即使训练后也难以完成 τ²-bench 的长流程 | 以 pass^1 为主指标（比 pass^4 宽松），同时报告结束原因，区分"不会协议"和"不会业务" |
| 语言迁移失败 | 英文沙箱占至少 50%；G1 节点专门检查 |
| τ²-bench 政策文档长、工具多，超出 0.6B 的有效处理能力 | 训练沙箱的政策长度和工具数量向 τ²-bench 靠拢（政策约 1,000–1,500 个英文单词，工具 10–15 个） |
| 用户模拟器不同（deepseek 与 gpt-4.1）导致成绩不可比 | 四组用同一个模拟器，只比较组间差异，不和榜单的绝对数值直接比较 |
| 训练时依赖平台约定，迁移时调用不存在的工具 | 平台工具名随机、默认不提供提交工具；用 heldout 命名探针量化 |

## 环境与已核实的机制（2026-10-13）

- 安装：两个 benchmark 依赖冲突（tenacity 9.2.1 与 8.5.0），各自装在独立虚拟环境 `.bench/tau2`、`.bench/bfcl`（不提交）。
  τ²-bench 的数据目录来自官方仓库，克隆在 `.bench/tau2-repo/data`，运行时设 `TAU2_DATA_DIR`。
  另外补装了缺失依赖：τ² 的 `websockets`、BFCL（qwen_agent）的 `soundfile`。
- τ²-bench 结束对话（源码 `user/user_simulator_base.py`、`data_model/simulation.py`、`run.py`）：
  - 用户模拟器输出 `###STOP###`（另有 `###TRANSFER###`、`###OUT-OF-SCOPE###`）结束对话；agent 调用 `transfer_to_human_agents` 转人工也会结束；
  - 结束原因包括 user_stop、agent_stop、max_steps（默认 100）、too_many_errors（默认 10）等。
- τ²-bench 判分（源码 `data_model/tasks.py`）：
  - 最终奖励是 `reward_basis` 中各项的乘积，默认是 `[DB, COMMUNICATE]`；
  - DB：最终数据库与"在全新环境中重放标准动作"后的状态一致，路径不限；
  - COMMUNICATE：每条 `communicate_info` 都以子串形式出现在 agent 的消息里；
  - ACTION（逐条匹配工具调用）只用在 banking_knowledge，airline、retail、telecom 不用。
- 与 V3 的对应：V3 自由对话已改为"用户道别即结束"，答案只做记录，结束时按最终状态、记录的答案和是否告知用户统一判分，
  结构与 τ²-bench 一致。不同之处在于 V3 是加权求和并有部分分，τ²-bench 是各项乘积、全有或全无。

## 方案修改记录

- 2026-10-13：用户决定**只做领域匹配的 C 组**，实验**先只看 τ²-bench**（BFCL 暂缓；第 1 节的 H2、H4 暂不评估）。
  - 训练池：`experiments/v3/bench/domains_tau_matched.json`，共 30 个领域，其中 12 个是航空、电商零售、电信客服（约占 40%），
    18 个是业务形态相近的服务业。通过 `--domains-file` 指定，不使用知识图谱采样，也不启用领域屏蔽。
    领域说明里写进身份核实、按政策拒绝、转人工等要求，代替第 4.2 节的新任务形态（生成流程本身不做改动）。
  - 生成参数：200 个沙箱，`--english-share 0.7`，`--rubric-share 0.05`，
    `--mix direct=0.1,simple=0.1,ordinary=0.2,complex=0.6`，自由对话的 policy gate，默认不提供提交工具。
  - 结论表述相应改为：用领域匹配的合成数据训练（数据由本项目生成，不含任何 benchmark 数据）。
- 推理服务：`experiments/v3/bench/serve_openai.py`，mlx-lm 生成，对话渲染（关闭思考）和工具调用解析与训练一致；
  τ² 运行脚本是 `experiments/v3/bench/run_tau2.sh`，用户模拟器为 deepseek-flash，温度 0，种子 300。

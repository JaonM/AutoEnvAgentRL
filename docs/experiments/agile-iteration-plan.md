# V3 小步快跑实验迭代计划（τ²-bench，Qwen3-0.6B）

状态：2026-10-13 制定。2026-10-14 晚第三版：汇总探路 SFT（A、B 两组）的结果和"一口气全查"习惯的根因分析，并纳入四块内容：工具真实感、按形态出题（新增 single_write）、世界模式的奖励可信、RL 的功劳分配（反向课程、树状 rollout）。SFT 和 RL 统一不开 think。

## 0. 原则

1. **每轮只改一个变量**，改完立刻快评。有提升才进入下一轮；没提升先诊断，**最多做一轮修复**，仍无提升就带着证据重新规划。
2. **不只看分数，也看行为**：每轮同时报告 pass^1 和行为指标（第 1 节）。分数持平但行为指标变好，记为方向正确；分数涨但行为变坏，不采纳。
3. **治根不治标**：发现坏习惯先查它从哪来（数据、环境、判分），不凭空添加限制。若调用方公开政策本身规定单轮工具数或禁止工具与正文混发，则按显式契约验证真实轨迹；不事后拆分、重写轨迹来制造合规。
4. **GPU 主线与工程支线并行**：GPU 只跑训练和快评；生成、测试、判分修复在支线做，成果只在两轮迭代之间并入。
5. **改平台身份的改动集中合并**：`runtime`、`core/`、`serving/`、`certify/`（除 policy gate）的改动只在批量构建空闲时合并，合并后统一 `verify --resign`。提示词、生产线、实验脚本不在此列，可以随时合并。
6. **τ² 测试题只用来打分，不用来出题**。2026-10-17 按用户授权，零售、航空世界可使用公开政策、工具实现和数据模型对齐业务语义；禁止把测试题、客户数据库、用户剧本及参考轨迹输入生成流水线。客户、业务记录和任务自行生成；诊断和定向补充以原创开发集为依据。
7. **控制随机波动**（2026-10-15 起）：同一份 A 数据训练三次，开发集平均奖励 0.274 / 0.345 / 0.292，单轮多调用 29% / 14% / 8%。因此每组至少 2 个种子、取平均；开发集检查报告置信区间；开发集 0.1 以内的差异不作结论；新组上线前先核对样本数和 token 数与预期一致（arm B 的近似成功样本被训练脚本静默丢弃，就是靠这一点才发现的）。

### 独立流水线的有界自动修复

`production/world.py` 已增加规格修复循环：保存每轮原始规格及审查意见，格式或契约不符时重写规格，再独立审查。调用方公开契约不可改；审查器返回无效 JSON 时停止，不能拿它当作业务错误继续改。规格修复与后续实现修复共享总预算。

`production/acceptance.py` 接入 build/batch 的 `--acceptance-suite` 和领域配置的 `acceptance_suite`。调用方提供固定检查器及预期值；构建开始前冻结哈希。检查失败后，隔离作者会话只可改 `env.py`，不能改 request、schema、verifier、政策、公开源文件或测试答案。每次修复重跑全部内部门禁和外部检查；无进展、预算耗尽、篡改、规格歧义、教师或基础设施错误均不会放行。模型服务没有执行的请求退还修复预算。当前实现修复入口仅支持独立业务 verifier；rubric 模式显式拒绝该选项。

验收套件 JSON 的 `checks` 每项包含 `name`、无 shell 的 argv `command`（替换 `{bundle}`、`{evidence}`）、`protected_files`（检查器及全部 oracle 依赖）、相对输出文件 `report`、`passed_field`；数量判定另设 `total_field`，要求 passed=total>0。失败类别通过 `failure_class` 声明；只有 `implementation` 可触发实现修复。`repair_context` 列公开来源。输入文件路径和命令程序建议使用绝对路径；未声明的依赖不在哈希保护范围内。

已有 bundle 的独立入口：

```sh
.venv/bin/python -m env_factory.production.acceptance \
  --bundle <original-bundle> --suite <suite.json> \
  --output <new-output-directory> --repairs 2
```

教师采集可显式启用 `--protocol-attempts 3`。违规草稿在任何工具执行前被拒绝，保留全部拒绝证据，不插入学生对话；到上限记为教师生成失败。默认 1 次仍保持原始采样口径，不能将两种策略混作同一个模型评测。

实证边界：新增本地测试用固定 runner 验证闭环控制、真实行为检查及不可篡改；尚不证明模型能自主修好任意新领域。航空原始版本的无模型回放内部门禁通过，但固定外部 API 仅 22/37，自动拦截，说明外部验收确有必要。真实 Codex 修复回放最初被自动审批拦截；用户随后明确授权，已按两轮上限执行。第一轮 API 达到 37/37，但用了沙箱禁止的 ast；第二轮 API 保持 37/37，但用了禁止的 nonlocal。最终自动拒绝，未人工修改候选代码、未放松规则。回放结论为“接口行为修复成功，完整自动修复失败”，详见 `airline/automatic-repair-replay-01/summary.json`。后续通用改进是向修复会话提供从实际 sandbox 导出的 `platform_rules.json` 和明确的当前 Python 自检命令；只完成本地测试，尚未做新一轮模型回放。独立验收覆盖的自动生成、公开来源冲突的正确裁决，以及新领域无人干预成功率仍须单独验证。当前航空、零售的既有人工修复历史完整保留；自动闭环不得追认它们为全自动产物。

用户随后明确：无依赖且名称/参数正确的多个工具调用可接受，正文和工具同发本身也不应直接视为业务错误。已核对官方源码并在当前安装的 τ² 运行时做合成探针（`tau2_protocol_probe.json`）：同轮多个调用被接受，内部按列表顺序执行；混合消息可解析，默认 enforce_communication_protocol=false，COMMUNICATE 能读到保存的正文。开启严格通信检查时混合消息报 AgentError。默认半双工调度把含 tool_calls 的消息发给环境，因此附带正文不会在该轮送给模拟用户；“评分历史看得到”不等于“用户听到了”。NL 评分也可读取保存的正文，但评分是否使用该组件由具体任务决定。

## 2. 到目前为止的结论

| 实验 | 结果 | 结论 |
|---|---|---|
| T0 | 不开 think 优于开 think | 统一不开 think |

**"一口气全查"的根因**（I2p-A）：
1. 教师一拿到编号，就把相关查询工具全查一遍：46% 的调用出现在单轮 3 个以上调用的回复里，34% 的查询结果后来没用上。我们的环境工具少、效率分宽松，这样做没有代价。
2. 0.6B 只学到了"批量发调用"的形式，没学到"手里有编号才查"的前提。没有编号时，它就照抄 τ² 工具说明里的示例值，比如 `#W0000000`。
3. 506 局里只有 36 局出现过失败调用，没有一次是"编号不存在"，所以模型从没见过失败后该怎么改正，只会原样重试。

## 6. 没有提升时的诊断顺序

1. 看行为指标和失败类型分布有没有按预期变化：没变，问题在数据或格式；变了但分数没变，问题在判分或评测口径。
2. 抽 10 条失败对话，和教师在我们环境里的成功轨迹并排比较。
3. 查训练和评测是否一致：模板、不开 think、工具名随机化、system 版式、工具说明里的示例值。
4. 只允许一轮针对性修复；仍无提升，就带着证据重新规划。
